  `details: unknown` and `status: number`, so callers can branch on codes like `insufficient_stock`,

Two contract details that are easy to get wrong — follow the CODE, not `API.md`:
1. The checkout request body key for acknowledging changed prices is **`price_acknowledgements`**, an
   array of `{product_id, new_price}`. `api/orders/views.py` reads exactly that key (search it to
   confirm). `API.md` calls it `acknowledged_issues` — the doc is WRONG. Do NOT "fix" it to match the
   doc, and do not leave a comment claiming the doc is right.
2. `POST /checkout/` requires an `Idempotency-Key` request header. `checkout()` must accept the key as
   an explicit argument from the caller (so a retry of the same attempt reuses it) rather than
   generating one internally per call.
